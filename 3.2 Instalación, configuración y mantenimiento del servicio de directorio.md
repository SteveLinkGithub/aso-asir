## Diseño de un directorio LDAP de una empresa

El objetivo de esta actividad es aprender a diseñar el árbol de entradas de un directorio de empresa utilizando los esquemas estándar de LDAP.

La información que se quiere gestionar en el directorio corresponde a una organización que se refiere como serveisbcn.com, con sedes en Barcelona y Sabadell.

La siguiente tabla resume la información que queremos en el directorio.

Por otra parte, se sabe que habitualmente las consultas se centran sobre los datos de una única sede, 
esto es, sobre la sede de Barcelona o la sede de Sabadell, pero no las dos a la vez.

Se le pide que diseñe el DIT y especifique las clases de objeto estándar y los atributos correspondientes.

Los pasos para realizar el diseño y escoger los componentes adecuados son:

1. Realizar el esquema gráfico del DIT teniendo en cuenta la raíz, las unidades organizativas propuestas y la previsión del tipo de consulta más habitual.
2. Mapear la información de la entrada con los atributos para poder determinar las clases de objeto.

De los tres estilos de la raíz (sufijo de directorio) escogemos arbitrariamente “dc=serveisbcn,dc=com”

Teniendo en cuenta que las consultas se harán mayoritariamente para una u otra sede, añadimos un primer nivel al árbol separando los datos de “ou=Barcelona” de los datos de “ou=Sabadell”. 
Así, se crean dos subárboles de búsqueda que permitirán aumentar el rendimiento de las consultas.

Teniendo en cuenta las unidades organizativas presentadas, 
añadimos un tercer nivel al árbol diferenciando “ou=equipamiento” y “ou=personal”.

El gran volumen de información serán entradas a partir de este tercer nivel, 
donde se encontrarán los objetos que representan empleados y equipos.

### A. Rama Estructural (Raíz y Sedes)

| Entrada (DN)                   | Tipo de Objeto | Clase de Objeto (`objectClass`) | Atributos Utilizados | Descripción                        |
| ------------------------------ | -------------- | ------------------------------- | -------------------- | ---------------------------------- |
| `dc=nodomain`                  | Raíz           | `top`, `domain`                 | `dc`                 | Base del árbol del directorio.     |
| `l=Barcelona,dc=nodomain`      | Sede           | `top`, `locality`               | `l`                  | Delimita la sede de Barcelona.     |
| `l=Sabadell,dc=nodomain`       | Sede           | `top`, `locality`               | `l`                  | Delimita la sede de Sabadell.      |
| `ou=people,l=...,dc=nodomain`  | Contenedor     | `top`, `organizationalUnit`     | `ou`                 | Agrupa a los empleados de la sede. |
| `ou=devices,l=...,dc=nodomain` | Contenedor     | `top`, `organizationalUnit`     | `ou`                 | Agrupa el hardware de la sede.     |

### B. Entradas de Datos (Empleados y Equipos) Para los Empleados:

Justificación de Clase Escogida: Se escoge inetOrgPerson porque es el estándar internacional en LDAP para almacenar cuentas de usuario con campos extendidos como correo electrónico corporativo y números de teléfono.

| Atributo LDAP     | Tipo de Dato Real      | Ejemplo de Valor                                         | Rol en el Directorio                               |
| ----------------- | ---------------------- | -------------------------------------------------------- | -------------------------------------------------- |
| `objectClass`     | Clases estructurales   | `top`, `person`, `organizationalPerson`, `inetOrgPerson` | Define las propiedades obligatorias de un usuario. |
| `uid`             | Identificador de login | `bcn.empleado` / `sab.empleado`                          | Identificador único (RDN) de entrada.              |
| `cn`              | Nombre completo        | `Empleado Barcelona`                                     | Nombre común legible.                              |
| `sn`              | Apellido               | `Usuario BCN`                                            | Campo obligatorio requerido por la clase `person`. |
| `telephoneNumber` | Teléfono fijo          | `931111111`                                              | Contacto de la oficina de la sede.                 |
| `mail`            | Correo electrónico     | `bcn.user@serveisbcn.com`                                | Dirección de e-mail de la empresa.                 |

### Para el Equipamiento (Equipos):

Justificación de Clase: Se escoge device debido a que es una clase estructural ligera diseñada específicamente para identificar elementos físicos e infraestructura tecnológica de red.

| Atributo LDAP  | Tipo de Dato Real    | Ejemplo de Valor                  | Rol en el Directorio                             |
| -------------- | -------------------- | --------------------------------- | ------------------------------------------------ |
| `objectClass`  | Clase estructural    | `top`, `device`                   | Define las propiedades de un dispositivo de red. |
| `cn`           | Nombre de host       | `pc-bcn01` / `pc-sab01`           | Nombre de la máquina (RDN de entrada).           |
| `description`  | Detalles de uso      | `Ordenador sobremesa Oficina BCN` | Texto explicativo de la función del equipo.      |
| `serialNumber` | Identificador físico | `SN-BCN-9988`                     | Número de serie del fabricante para inventario.  |

| Ejecutable   | Ubicación             | Tamaño aprox. | Función principal                                 |
| ------------ | --------------------- | ------------- | ------------------------------------------------- |
| `slapd`      | `/usr/sbin/slapd`     | ~2.4 MB       | Servidor: es el motor central de OpenLDAP.        |
| `ldapadd`    | `/usr/bin/ldapadd`    | ~120 KB       | Cliente: inserta datos desde archivos LDIF.       |
| `ldapmodify` | `/usr/bin/ldapmodify` | ~120 KB       | Cliente: modifica o borra atributos.              |
| `ldapsearch` | `/usr/bin/ldapsearch` | ~160 KB       | Cliente: busca y consulta datos en el árbol LDAP. |
| `ldapdelete` | `/usr/bin/ldapdelete` | ~100 KB       | Cliente: elimina entradas completas (DN).         |
| `slapcat`    | `/usr/sbin/slapcat`   | ~50 KB        | Herramienta: exporta la base de datos a LDIF.     |
| `slapadd`    | `/usr/sbin/slapadd`   | ~50 KB        | Herramienta: importa datos en frío (sin red).     |


**Análisis de los resultados:**

1. Seguridad de rutas: Las herramientas de administración interna **(/usr/sbin/)** están separadas de los comandos de usuario común **(/usr/bin/)** para proteger el acceso al motor.
2. Ligereza técnica: Los clientes ocupan muy poco espacio porque el procesamiento pesado recae directamente sobre el demonio principal **(slapd)**.
3. Binarios idénticos: **"ldapadd"** y **"ldapmodify"** tienen exactamente el mismo tamaño porque comparten el mismo código fuente para optimizar el almacenamiento del sistema.
